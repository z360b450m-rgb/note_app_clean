# 让助手安排复习：关联组题、确认、直接进入复习

错题卡片的主按钮使用关联复习接口。点击后从当前错题本已有题目中组成一组，
默认最多 10 道，当前题固定作为第一道，先保留至少 3 道召回题，再追加关联题并去重。
当前错题本题量不足时按实际题量返回。预览显示题目、召回或关联理由、复习/答错次数和预计用时。
点击“确认并进入复习”后，按确认的 ID 列表和顺序直接进入 ReviewPanel；
不再打开普通复习筛选框，也不重新随机选题。原有作答、理由追问和智能判卷流程继续使用。

## 组题策略

1. 用登录凭证读取当前题，范围限定同一错题本，允许主动复习未来排期题。
2. 复用现有错题语义检索路线：Milvus 检索题干与解题结构的稠密/稀疏向量，Neo4j 扩展共享知识点、
   材料和题对声明，再按已有融合策略合并排名，最多49道其他题。按召回顺序回读MySQL真实记录，
   删除/移出当前本的候选剔除。实际语义候选不足3道时，才用标签/词项和同本风险候选补充。
   检索范围限定已验证用户、当前错题本与已发布索引版本；召回只是线索，不表示题目已经相关。
3. 核对同一核心概念、必要前置方法、迁移应用三种关系；非未知关系需要当前题和
   对应候选题各自的原文引文。仅学科、标签或字面相似不能证明关系。
   使用完整业务正文分批核验，每批最多8题、约18000字预算，最多4批并行；单批失败保留其他批次结果，
   返回partial和失败批次数，不再把大量候选的每题材料/答案统一压到180字后淘汰。
   双方引文逐条验证，额外超长/不匹配引文剔除；仅两侧分别仍有有效短引文时保留关联，输出中不携带无效引文。
   模型引文与PDF文字只有空白差异时，恢复实际原文片段再交由业务端逐字校验；数字、标点和文字差异仍拒绝。
   每批局部编号，返回后映射全局候选，避免模型重置序号导致整批失效；超长说明按接口上限截取。
   超长引文仅在整条匹配原文后取120字展示，不接受未经匹配的任意前缀。
4. 保留召回顺序中的前 3 道不同题目（不含原题），叠加通过关联核对的真实题目并去重。
   保底题不被追加题挤出，总数最多 10 道。当前题保留在首位，其他题按错误风险 × 教学重要性排序。
   风险复用已评估模型或 Beta 回退，重要性复用 1/1.25/1.5 的策略权重。
5. 没有足够关联证据或模型核验失败时仍保留召回题，关系标记为 `recalled`，双方关联引文为空，
   明确显示“召回补充题，关联尚未确认”。当前本题量不足 3 道时按实际数量补充，无其他候选时只保留原题。
   原文截断或图形未能读取时不猜关联。
   已入库候选的保底题显示真实召回线索（共享材料、任务数量关系、命中通道及差异），保持待核验状态。
   模型正向关系与理由中明确的“应判无关”相矛盾时，不能把该项作为已核验关联追加。

这是 AI 教学建议；引文校验约束出处，不构成语义判断正确性的数学证明。
当前不生成新的个人错题，不把不存在的题目加入用户复习记录。

## 接口

`POST /api/entries/{anchor_entry_id}/review-bundle`

```json
{"limit":10}
```

limit 默认 10，允许 4 到 10（包含原题）；它是题量上限，不会为凑满上限增加未核验的保底3题以外的题目。
需要登录。返回 anchor_entry_id、notebook_id、proposal_token、expires_at、items、
estimated_seconds、notices、bundle_version。items 中没有参考答案，仅包含题目预览、
关联理由和双方引文、重要性建议、用时及复习计数。
另返回 `retrieval`，包含召回状态、候选/回读数量、stem/structure/graph命中通道及降级提示；
页面显示召回线索，索引缺失或服务不可用时明确说明补充来源。

`POST /api/entries/{anchor_entry_id}/review-bundle/confirm`

```json
{"proposal_token":"预览响应中的签名草案"}
```

确认仅接收签名草案，不能传入替换题目的 entry_ids。再次核对账号归属、错题本范围及
每道题的正文指纹；题目修改返回 409，删除或失去权限返回 404。成功返回同顺序 entry_ids。
前端还会核对它与预览列表完全一致；任一题加载失败时不启动部分题组。

草案采用用途隔离的 HMAC 签名，绑定账号、当前题、错题本、题目顺序、正文指纹及
15 分钟有效期；签名派生自现有 JWT_SECRET_KEY，草案不能用作登录令牌。
确认可以重复执行，不修改复习日期、掌握等级、日志或计数，不需要新数据库迁移。
过期、范围或版本变化后需要重新组题。未保存编辑时，按钮提示先保存再组题。

业务后端调用查询服务只读 `POST /review/bundle`，请求 entry_id/limit。
查询服务再次验证登录，调用业务端 review-candidates 和 related-candidates；
模型只按索引关联候选，不输出业务 ID。业务端再检查候选 ID、来源、已核验关系的双题引文和重要性依据；
`recalled` 只表示召回补充，仍验证账号、错题本及正文版本，但不得携带未经核验的关联引文。

`POST /api/review-agent/related-candidates` 仅为登录后的只读召回接口，
请求 anchor_entry_id、concepts（最多6个短词）、limit（最多50）。
当前复习队列在前端，完成判卷才由 review-attempts 原子写日志与计数。
