# PDF 错题导入策略（MinerU）

完整策略与三份样例验收基准位于查询服务仓库：

[MinerU PDF 错题导入策略](G:/pycharm/shopkeeper_brain/docs/pdf_wrong_entry_import_strategy.md)

本仓库承担任务归属、导入预览、图片持久化、题组/错题事务录入和幂等确认。
查询服务承担 MinerU 解析与题目结构化，不直接写错题 MySQL 主数据。

核心要求：

- 一拖多以共同依赖公共材料判断，覆盖文字、图表、图形和混合材料；同页或同知识点不能作为充分依据。
- 公共材料进入 `QuestionGroupModel.material`；子题本身的图片仍进入本题，不能二选一。
- 图形样例第 4 题跨页；资料分析样例第 5 题既属于第 2 个题组，也有自己的趋势图。
- 文字独立题保持原题干和选项，跨页时续接；不按任意文本长度切题。
- 保留原图和来源，OCR/图像描述是辅助，不能替代题干中的真实图像。
- 样例 13 道题均缺少原文答案、作答和解析，收录后显示待补充，不能虚构评分或复习记录。
- 解析后先产生草稿预览，确认后批量事务录入；业务录入和检索索引分离。

当前已实现上传 → MinerU 解析 → 图文草稿校对 → 勾选确认 → 事务录入。明确材料范围限制成员；不充分的材料关系展示候选提示。可以调整已有题组归属，拆组时保留公共材料，缺失的答案/作答仍留空。

任务及图片保存在 `.data/pdf-imports`（可配置 `PDF_IMPORT_STORAGE_DIR`），图片通过签名链接访问。`RAG_AGENT_URL` 默认指向 `http://127.0.0.1:8001`；`PUBLIC_NOTES_API_URL` 默认是 `http://localhost:8000`，部署时设为前端能访问的后端地址。解析服务使用 `requirements-question-import.txt` 的 MinerU 3.4.5 协议，未知输出版本会报错，避免误读。

已通过三份实际 MinerU 结果与隔离 SQLite 录入验证：13 题、2 组、8 张题图，确认重试不重复保存，复习次数与复习日志不增加。浏览器验证包含校对、选择题目、确认响应丢失重试、图片加载、窄屏与深色布局。真实用户数据库没有写入样例。

当前后台任务没有独立持久队列；重启中断的解析会在超时后提示重新上传。尚未提供新建材料组、图片归属拖动和离线归档图片嵌入。扫描、多栏等复杂版式仍需人工校对和更多真实样例验证。
